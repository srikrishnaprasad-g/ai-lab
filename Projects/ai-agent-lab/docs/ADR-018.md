# ADR-018: Structured LLM Response Validation

Status: Accepted

Problem:
The LLM (Gemini) occasionally returns unstructured Markdown, code fences, or conversational filler instead of the expected raw JSON, breaking the downstream PDF generation pipeline.

Context:
- `SummaryAgent` requires strict JSON input for parsing into `SummaryResult`.
- Simple `json.loads` fails when the provider includes non-JSON content.

Chosen Solution:
Implement a robust, multi-stage parsing strategy in `SummaryAgent`:
1. Strip leading/trailing whitespace.
2. Use a regex to extract the first '{' and last '}' to isolate JSON content.
3. Validate the presence of required schema fields (`executive_summary`, `key_findings`) before attempting to populate the `SummaryResult` domain model.

Consequences:
- Significantly improves parsing reliability.
- Fail-fast approach: Parsing/Contract validation errors now propagate correctly through the `AgentResult` error mechanism rather than masking them with placeholder content.

Future Considerations:
- Extract the JSON parser into a reusable infrastructure component (TD-017).
