# ADR-017: LLM-Backed Summary Agent Integration

Status: Accepted

Decision:
The SummaryAgent will directly utilize an injected `LLMProvider` to perform summarization, replacing simulated logic. The `LLMProvider` is accessed through existing abstractions, and prompt construction is handled by `SummaryPromptBuilder`, delivering separate `system_prompt` and `prompt` fields to the provider, which are correctly mapped to the Gemini API payload.

Rationale:
- Necessary to fulfill the MVP requirement of generating a populated PDF report based on research results.
- Uses existing provider infrastructure, maintaining decoupling between agents and LLM implementations.
- Separating system and user prompts improves LLM instruction compliance and JSON output quality.

Consequences:
- `SummaryAgent` now has a hard dependency on `LLMProvider` (via constructor injection).
- Improved report quality and structure due to LLM-driven synthesis.
- Requires robust JSON parsing logic in `SummaryAgent` to handle potential LLM verbosity.

Future Considerations:
- Consider moving JSON parsing logic into a reusable `LLMResponseParser` component to simplify Agent implementation.
