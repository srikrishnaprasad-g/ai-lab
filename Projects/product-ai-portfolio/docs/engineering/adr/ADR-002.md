# ADR-002: Technology Stack Selection

## Purpose

Define the standard technology stack for AI-Lab web applications and establish principles for evaluating future technologies.

---

## Context

AI-Lab will host multiple long-lived products over several years.

Choosing technologies solely based on popularity creates inconsistency and increases maintenance costs.

A standardized stack promotes reusable components, consistent engineering practices, and easier onboarding.

---

## Decision

The default technology stack for AI-Lab web applications is:

| Layer | Technology | Rationale |
|--------|------------|-----------|
| Framework | Next.js | Production-ready React framework with App Router, SSR/SSG support, and excellent ecosystem |
| Language | TypeScript | Static typing, maintainability, and safer refactoring |
| Styling | Tailwind CSS | Utility-first styling with responsive design support |
| UI Components | shadcn/ui | Accessible components with full source ownership |
| Icons | Lucide React | Lightweight and tree-shakeable |
| Package Manager | npm | Stable default package manager |
| Linting | ESLint | Consistent code quality |
| Formatting | Prettier | Automated code formatting |
| Hosting | Vercel | Native Next.js deployment experience |
| Version Control | GitHub | Industry-standard source control |

---

## Engineering Principles

- Prefer mature technologies over experimental ones.
- Favor convention over customization.
- Every addition to the stack must have documented justification.
- Minimize unnecessary dependencies.
- Prioritize long-term maintainability.

---

## Supported Languages

- TypeScript
- Markdown
- JSON
- YAML

---

## Rationale

This stack provides an excellent balance between developer productivity, scalability, maintainability, and ecosystem maturity.

It also aligns with the requirements of AI-Lab projects while minimizing operational complexity.

---

## Alternatives Considered

- React + Vite
- Astro
- Remix
- SvelteKit
- Nuxt

These remain valid choices for future projects but are not the default AI-Lab stack.

---

## Consequences

### Positive

- Consistent developer experience
- Easier onboarding
- Reusable components
- Predictable deployment pipeline

### Trade-offs

- Reduced flexibility for one-off experiments
- Periodic technology reviews required
