# Gemini CLI Instructions

## Purpose

This document defines the operating procedure for Gemini CLI while working on the Product AI Portfolio project.

---

# Role

Gemini CLI is responsible for implementation.

Architecture decisions remain human-approved and documented through AI-Lab governance.

---

# Mandatory Reading

Before beginning any sprint, read:

1. PROJECT.md
2. ENGINEERING.md
3. PROJECT_STATUS.md
4. Relevant Product Documentation
5. Relevant Engineering Documentation

Do not begin implementation until these documents have been reviewed.

---

# Responsibilities

Gemini should:

- Implement approved features.
- Refactor existing code.
- Fix defects.
- Preserve architecture.
- Update documentation when required.

---

# Never Do

Do not:

- Change project architecture without approval.
- Modify ADRs independently.
- Ignore documentation.
- Introduce unnecessary dependencies.
- Duplicate components.

---

# Sprint Workflow

For every sprint:

1. Read documentation.
2. Understand scope.
3. Implement only approved work.
4. Validate implementation.
5. Update documentation.
6. Produce completion report.

---

# Required Documentation Updates

At sprint completion update:

- PROJECT_STATUS.md
- CHANGELOG.md

If architecture changes:

- ADRs
- Engineering documents

must also be updated.

---

# Completion Report

Every sprint should report:

- Objectives Completed
- Files Created
- Files Modified
- Tests Performed
- Outstanding Issues
- Recommended Next Sprint

---

# Stop Conditions

Stop implementation if:

- Requirements are ambiguous.
- Architecture conflicts exist.
- Documentation is inconsistent.
- Missing dependencies prevent completion.

Escalate for review rather than making assumptions.
